# KHR_interactivity Integration

## Current Khronos Status

Official Khronos sources reviewed on 2026-07-17:

- Khronos' glTF extension registry lists `KHR_interactivity` as a Release Candidate in the in-progress roadmap, not as a ratified extension.
- The draft specification lives on the KhronosGroup/glTF `interactivity` branch and defines a root-level `extensions.KHR_interactivity` object with `graphs`, `graph`, `types`, `variables`, `events`, `declarations`, and `nodes`.
- The draft defines custom event receive/send operations for external execution environments and behavior graphs.
- Khronos' public comment post frames the extension as sandboxed behavior graphs for portable glTF assets.

References:

- https://github.com/KhronosGroup/glTF/blob/main/extensions/README.md
- https://github.com/KhronosGroup/glTF/pull/2293
- https://raw.githubusercontent.com/KhronosGroup/glTF/interactivity/extensions/2.0/Khronos/KHR_interactivity/Specification.adoc
- https://www.khronos.org/blog/gltf-interactivity-specification-released-for-public-comment

## Integration Scope

This is a vertical slice, not a universal `KHR_interactivity` player.

The game loads one generated glTF asset:

- `assets/interactive/quantum-ball.gltf`

The asset contains:

- glTF 2.0 sphere geometry for the player ball core, halo, and shell.
- `extensionsUsed: ["KHR_interactivity"]`.
- A root-level `extensions.KHR_interactivity.graphs[0]` graph.
- Custom events for source-ball presentation state.
- Variables for `presentationState`, `charge`, and `impact`.
- A delayed `event/send` path for `QB_VISUAL_COMPLETE`.

The asset does not list `KHR_interactivity` in `extensionsRequired`, so viewers without interactivity support can still render the ball.

## Runtime Modules

- `interactivity/extension-loader.js`: fetches the glTF JSON, parses it with Three's `GLTFLoader`, and keeps the raw document available for extension parsing.
- `interactivity/graph-parser.js`: validates the supported graph shape and reports unsupported pieces.
- `interactivity/graph-runtime.js`: executes the supported operations.
- `interactivity/event-bridge.js`: carries host-to-asset and asset-to-host events.
- `interactivity/state-store.js`: owns graph variables and exposes named variable metadata from `extras`.
- `interactivity/host-bindings.js`: maps graph state to Three presentation for the source ball.
- `interactivity/diagnostics.js`: feeds the hidden in-game diagnostics overlay.

Supported operations are intentionally narrow:

- `event/onStart`
- `event/onTick`
- `event/receive`
- `event/send`
- `flow/sequence`
- `flow/setDelay`
- `variable/get`
- `variable/set`
- `debug/log`

Unsupported operations are reported and treated as no-op. This avoids inventing semantics while the extension remains in flux.

## Host Ownership

The game remains authoritative for:

- Aiming, cue input, and shot power.
- Table geometry and path tracing.
- Target hit scoring and clear/fail rules.
- Arcade run timing, grading, unlocks, Newgrounds adapter calls.
- WebXR session and controller aiming.

The asset owns local presentation state only:

- `Idle`
- `Selected`
- `Charging`
- `Released`
- `Colliding`
- `Quantum-active`
- `Collapsing`
- `Pocketed`

## Event Contract

Host to asset:

- `QB_SELECTED`
- `QB_DESELECTED`
- `QB_CHARGE { charge: float }`
- `QB_RELEASED { charge: float }`
- `QB_COLLISION { impact: float }`
- `QB_QUANTUM { impact: float }`
- `QB_COLLAPSE`
- `QB_POCKETED`
- `QB_RESET`

Asset to host:

- `QB_VISUAL_COMPLETE`

`QB_VISUAL_COMPLETE` is sent by the graph after `QB_COLLAPSE` via `flow/setDelay`, then `event/send`.

## Rebuild And Test

From `outputs/quantum-billiards`:

```sh
npm run build:assets
npm run test:interactivity
npm run package:newgrounds
```

The asset build is deterministic and generated by:

```sh
node tools/build-quantum-ball.mjs
```

The harness is available at:

```text
harness/quantum-ball-harness.html
```

Run it through a local server, not by direct `file://`, because the loader fetches the glTF asset.

## Diagnostics

In the game, press `I` to toggle the hidden diagnostics overlay. It shows:

- Current runtime status.
- Graph variables.
- Recent host-to-asset and asset-to-host events.
- Parser/runtime warnings.

## Known Limits

- This is not a full implementation of the Release Candidate spec.
- No `pointer/*`, animation control, interpolation, physics, hoverability, or selectability extension runtime is implemented yet.
- The glTF asset is `.gltf` JSON with embedded binary data URI, not `.glb`.
- Three.js loads the geometry, while our adapter executes the supported graph subset.
- The integration is scoped to the source ball. Targets and tables remain procedural for now.
